# Agent Note: 「ETF托底」副图（ETF 份额渗透率量化救市深度与广度）

Status: implemented

## Problem

用户提出一个可观测的救市代理指标：国家队救市主要买大市值宽基 ETF，于是「沪深300 ETF 规模 ÷ 沪深300 成分股市值」可以量化救市**深度**；而「被买入的 ETF 从沪深300 扩散到 A500 / 中证1000」可以量化**广度**。要求做成大盘指数的副图指标。

三个障碍都不是渲染问题：

1. **指标没有取数能力**。`IndicatorDefinition.compute` 只吃 `(bars, params)`；ETF 份额是交易所按交易日披露的**外部日频序列**，不是从 K 线派生的量。[hk-connect-holding](2026-10-12-hk-connect-holding-indicator.md) 已建好 `aux` 注入缝，本指标是这条缝上的第三个消费者（第一个双键消费者）。
2. **需要的是「份额」而非「行情」**。ETF 的场内份额每个交易日收盘后由两所各自披露，`push2` 类行情端点只给价格与一个当日规模快照（无历史）。要能回看 2024-02 与 2024-09 两次救市，必须有按日期回溯的份额历史。
3. **分母有两个互相矛盾的要求**：用户要「占自由流通股的比例」，而沪深300 的自由流通市值**没有免费日频源**——中证指数官网 `index-basic-info` 只有 30 个描述性字段、`index-perf` 只有 OHLC/成交额/成分数，东财指数行情只有 `f116` 总市值与 `f117` 流通市值。

## Decision

**数据侧：交易所披露的份额 × 基金单位净值 ÷ 指数流通市值，落成本地增量缓存，经可选能力 + 桥端点供给指标。**

- **契约（`@dshtrading/api`）**：`EtfRescuePoint { date, depthPct, breadthPct }` + `EtfRescueHistory { symbol, indexCode, depthLabel, points }` + `MarketDataService.getEtfRescue?(symbol)`（additive，存量连接器零迁移）。`date` 归一到 UTC 当日 00:00，与日 K `openTime` 同口径。标的不映射宽基指数时返回空 `points` 且不触网（**空 ≠ 0**）。
- **连接器（`connector-akshare`）**：五个上游——上交所 `query.sse.com.cn/commonQuery.do`（`COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L`，按 `STAT_DATE` 逐日取全市场，`TOT_VOL` 单位万份）×1、深交所 `www.szse.cn/api/report/ShowReport`（`scsj_fund_jjgm`，xlsx 区间导出，单元格是 `inlineStr` 且基金代码带尾随空格）、天天基金 `api.fund.eastmoney.com/f10/lsjz`（单位净值）、腾讯 `web.ifzq.gtimg.cn`（七个指数的日线收盘——中证官网 `index-perf` 对 399006 返回空数组）、东财 `push2`（指数流通市值标定）。缓存落 `<trading home>/etf-rescue/`，按 (交易所, 交易日)/(代码)/(指数) 分文件、记水位增量补齐，起点 2023-01-01。
- **口径（冻结）**：`规模_etf,t = 份额 × 单位净值`；`深度_t = Σ规模(该标的所属指数篮子) ÷ 流通市值(该指数) × 100`；`广度_t = Σ规模(除沪深300 外六个篮子) ÷ Σ流通市值(那六个指数) × 100`。指数流通市值 = `k × 收盘点位`，`k` 由东财 `f117 ÷ f43` 标定后缓存 90 天。某交易日缺份额或缺净值的那只 ETF 不参与当日合计，全部不可得则当日不出点。
- **篮子（冻结白名单，代码是唯一事实）**：000016→510050；000300→510300/510310/510330/159919；000510→563360/512050/159338；000905→510500/159922；000852→512100/159845；000688→588000/588080；399006→159915。
- **桥端点**：`GET /dshtrading/api/etf-rescue?market=cn&symbol=`，能力解析沿「active 优先 → 同市场按 provider 名升序取首个实现者」的既有候选序，5 分钟 TTL + 同键 in-flight 去重。非 cn 市场与能力缺席回**内联** `{ok:false, code, message}`（HTTP 200）而不抛——「这个部署没有该数据源」是稳定能力事实，不是本请求的异常；上游失败仍抛，走统一错误信封。
- **指标**：预置 `cn-etf-rescue`（title `ETF托底`，`pane: 'sub'`，`markets: ['cn']`，无参数，不默认上图），`aux` 声明两条键 `cn-etf-rescue-depth` / `-breadth`，`compute` 返回 `[]`、`computeAux` 出两条 line `ETF渗透%` / `非300渗透%`（precision 2）。任一键缺席或为空 → 返回 `[]`（整块副图隐藏，只画半块会让读图的人把缺的那条当 0）。对齐用预设局部的**区间精确匹配** `alignAuxToBarCoverage`，**不用**前向填充的 `alignAuxToBars`：深度/广度是「某一日的当日存量占比」，跨日沿用会把昨日读数画成今日。
- **图例带 %**：指标契约的 `priceFormat` 只认 `'price' | 'volume'`（`packages/indicators/src/types.ts`），纵轴没有百分比格式，0.96 这种量级会被渲染成裸的 `0.96`——单位由图例承载，不改通用轴格式化（那会波及所有副图指标）。
- **客户端**：两条键读同一个端点，`createEtfRescueMemo` 在每次刷新时建一份请求级 memo，一批里两条键只发一次 GET（跨批不复活：换标的守卫仍在 `useAuxSeries`）。空态文案按键分派（深度缺 = 没映射到宽基指数，广度缺 = 六篮子整体取不到）。

## Alternatives considered

- **分母改用自由流通市值**：最贴用户原话。否决于数据可得性——没有免费日频源，只能造一个固定折算系数，等于用一个常数假装成测量值。落地为「占**流通市值**」，并在 `EtfRescueHistory` 与指标 description 里写明分母口径。
- **广度剔除中证A500 以换取口径稳定**：A500 指数 2024-09-23 才发布，占六篮子流通市值 44.7%，加入当天广度读数一次性下降 46%（实测 2024-09-20 的 0.997% → 09-23 的 0.538%）。剔除后曲线无台阶，但会丢掉 2025 年最主要的救市载体。**用户裁决保留六篮子、接受台阶**，故在指标 description 里写明「这是构成台阶，不是资金行为」。
- **广度改成各篮子渗透率的等权平均**：不受单篮子市值权重主导、也没有台阶。否决——「合计规模 ÷ 合计市值」有明确经济含义，等权平均没有。
- **指数流通市值直接读 `push2/api/qt/stock/get` 的 `f117`**：契约主路径。本机实测该端点 10/10 传输层空回（`OpenSSL SSL_read: unexpected eof`），实现按同域 `ulist.np/get` 的 `f21 ÷ (f2/100)` 等价兜底（2026-11-22 实测 000300 两者差 0.58 元），缓存条目以 `source` 字段留痕，`stock/get` 恢复后下次标定自动走回主路径。
- **每日 cron 采集落盘（照 active-buy 的 `snapshots.jsonl` 模式）**：需要长期跑定时任务，且历史只能从部署日起积累。否决——两所都能按日期回溯（上交所按日、深交所单次 ≤3 个月），按需回溯 + 增量缓存即可，不需要后台任务。
- **用 ETF 的成交额/成交量当救市代理**：完全不需要份额数据。否决——成交额是流量、份额是存量，救市最硬的证据是「份额净申购且价格没跌」，成交额分不出谁在买。

## Consequences

- **序列与形态（2026-11-22 实测，2023-01-03 至 2026-11-20 共 940 个点）**：沪深300 深度从 0.295% 起，2023-12 的 0.616% → 2024-02 的 1.165%（两个月 +89%）、2024-06 的 1.312% → 2024-09 的 2.021%，峰值 2025-04-21 的 2.160%，2026 年赎回压到 0.373% 后回到 1.054%。广度 0.390% → 0.560%。两个救市时段与赎回时段都能一眼读出，指标在语义上成立。
- **冷启动成本**：一次全量回溯约 252 秒、约 120 MB 上游流量；暖缓存重复调用 55–67 毫秒、零请求。取数按文件水位增量，中断后下次从水位继续，因此首次打开副图的用户会先看到空态、若干次刷新后收敛。没有做后台预热（YAGNI：一次性成本，且按需回溯已保证收敛）。
- **已知上游边界**：基金净值端点 `pageSize` 硬上限 20（传 2000 回 `Data:null`），实现按 `TotalCount` 翻页；深交所份额 xlsx 单次窗口按 3 个月切分（实测 5.7 个月窗口在 65536 行处截断并丢掉最早日期）；深交所只认 `SHOWTYPE=xlsx`（csv/txt 回 500）。
- **合规面变化**：`connector-akshare/README.md` 原有的「本仓不缓存、不再分发行情数据」对新能力不再成立，改写为「交易所与基金净值公开披露只落本地缓存用于增量补数、不对外分发」。这是本包第一次落盘持久化上游披露数据。
- **两条键可以由同一次应答供给**：`aux` 机制的既有事实是「一条键一条取数分支」；本指标引入「两条键共享一次端点应答 + 请求级 memo」。新增同族指标时，若两条序列同源（同一响应按口径拆分）应复用 `createEtfRescueMemo` 的形状，而不是各发一次请求。
- **纵轴无 %**：副图右轴是两位小数的百分比数值（`1.00/1.50/2.00`），单位只由图例的 `%` 承载。要让轴自己带 `%` 需要动通用 `outputPriceFormat`，影响所有副图指标，本次不做。
- **证据**：`node scripts/ui-component-check.mjs --harness packages/client-ui-trading/harness/etf-rescue-sub-pane.harness.tsx` 出图（图例 `ETF渗透%: 1.19` / `非300渗透%: 2.19`，两条线 2590px/2325px 落笔、跨度 33px/49px、轴 precision 2、组 `["ETF渗透%","非300渗透%"]`）；跨包接缝校验用真实缓存喂 `etfRescueToAuxPoints` → `computeAux`，940 点全对齐、零坏值、与源数据逐位相符。
