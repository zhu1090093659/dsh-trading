# Agent Note: 「发给 Agent」快照升级——序列时间范围 + 取数位置 + 已开指标当根读数随消息透出

Status: implemented

## Problem

「发给 Agent」落地语义只填入快照摘要（现价/涨跌/昨收 + 十字线读数当根 K 线 OHLCV + 已开指标**标题**）+ 图表截图（[2026-09-02 记录](2026-09-02-watchlist-agent-visibility-and-send-to-agent.md)、[2026-09-04 入口统一](2026-09-04-unified-send-to-agent-entry.md)）。owner 2026-09-05 实测两个缺口：

1. **序列不在场**：用户选日 K，Agent 收到的只有「当根」读数——图表序列从多久到多久、共几根、去哪取，Agent 全都不知道；对着截图觉得没用（视觉输入难读数），只能自己再去抓标的行情，抓取口径（数据源/周期/条数）还未必与用户所见图表一致。
2. **指标只有名字没有数值**：快照列「已开启指标：MA、MACD」，但指标算出的结果数值不在场——Agent 要么瞎猜、要么按默认参数复算一套与用户图上的线对不上的值。

## Decision

owner 2026-09-05 两段裁决合成现状：**K 线数据不内联**（「Agent 分析行情应该用那些工具、写代码来做」）＋ **指标直接发计算结果**（「告诉一个参数他还要自己算，多此一举」）。新纯函数 `compose-quote-data.ts`（与 `compose-quote.ts` 同款「词典注入可测」范式）在快照摘要之后追加数据位置段：

1. **范围行**：`首根 ~ 末根 · 共N根 · interval=<周期id> · 本地时区`（日线类周期落日期，盘中周期落到时分；注明最新一根为进行中的当根 K 线，防止把范围误读成已收历史）。
2. **取数位置行**：`<market>_get_klines` 工具（各市场连接器统一注册，与图表同一路由数据源）+ 同参 `symbol / interval / limit=根数`——Agent 按此调工具即可取得同源序列，limit 给的是用户图上实际根数（复取的总是最新 N 根）。
3. **指标读数行**（无有效读数时整行省略）：已开指标的计算结果数值直接透出，口径 = 图表读数行（与快照「当根K线」同根：十字线悬停处，未悬停即最新一根）；每个实例 `标题 key=value, ...`（legend 同款两位小数，output key 自描述如 MA5/DIF/DEA），warm-up 未就绪分量跳过、整组无值整组省略。数值与渲染同源（前端注册表 compute 输出），不存在「参数对不上」问题。
4. **i18n**：`compose.data.*` 4 键（contract 键 union + zh/en 词典同步，占位符对齐），模块缺省回落 zh 常量（文件头 `i18n-allow:` 豁免，与 compose-quote.ts 同款）。
5. **测试**：新 `test/compose-quote-data.test.ts` 5 例（全量/读数 warm-up 跳过/无读数省略 + 盘中范围/空序列/zh 缺省文案），时区敏感断言走同源 helper 与本地时区时间构造。快照摘要（compose-quote.ts）与填入通道（fill-composer.ts）零改动。

## Alternatives considered

- **内联 K 线全序列 + 指标逐柱数值 CSV**（本记录初版方案，已提交后当日被 owner 否决）：数据自足、Agent 少一轮工具调用，但「直接发给他的话，Agent 也没法分析」——行情分析应调工具取数后写代码完成，输入框里的几百行 CSV 既不可读也不可算，还把 composer 草稿撑到几十 KB。落选（否决裁决归 owner 2026-09-05）。
- **指标只透出参数、指引 Agent 同参复算**（第二版方案，同日被 owner 否决）：「告诉一个参数他还要自己算，多此一举」——参数值不等于结果值，Agent 复算多一轮工具调用还可能与图上读数有出入；直接发当根读数与图表 legend 同源同参，零歧义。落选。
- **只给取数工具不给范围**：消息最轻，但 Agent 无法判断「用户看到的序列」与工具返回序列是否对得上（周期内进行中 K 线、复取时市场前进），分析结论可能锚错窗口。落选。
- **指标只发名字或最新读数**：体积最小，但复算参数不在场时 Agent 只能按默认参数算，与用户图上的线不一致——参数透出是同参复算的最低要求。落选。

## Consequences

- 「发给 Agent」草稿 = 快照摘要 + 数据位置段（K 线序列未就绪 `klines === null` 时整段省略，快照兜底）；草稿体积相比旧版只多三行，composer 可用性不变。
- 指标当根读数与图表 legend 完全同源同参（前端注册表 compute 输出）；Agent 若需指标**序列**做形态分析，仍可经自有工具（`<market>_get_indicators` 等，描述可自行发现）复算——消息不再为此指路。
- 复取的总是**最新** N 根：快照到 Agent 取数之间市场若前进，序列窗口相对快照右移——范围行的价值在于标定用户当时所见，Agent 需结合时间戳自行对齐（已注明进行中 K 线）。
- 消息不再承载行情数值本体：截图与数值的视觉/机器冗余由 Agent 侧工具调用补齐，token 成本随分析深度按需发生，而非每次投递固定支出。
- dsh-i18n 中心包维护契约再次确认：源包词典改动必须「先重建源包、再重建 dsh-i18n、再跑 `pnpm i18n:check`」（audit 读 lib 产物）。
