# Agent Note: 交易终端「模拟交易 (Paper Trading)」UI 布局与本地撮合引擎

Status: implemented

## Problem

交易终端此前已打通真实实盘报单（`dryRun: false`）与连接器错误阻断机制。为了让交易员无需申请真实 API Key 即可低门槛练习盘感、验证策略，需要引入全功能模拟交易（Paper Trading / Demo）系统。

在主流专业交易所（OKX、Binance、富途牛牛、TradingView）中，模拟交易必须具备：
1. **零混淆与强防错**：交易者在看盘敲单时，必须一眼识别当前是实盘真钱还是虚拟资金；
2. **全局模式双轨**：下单面板与资产账本同频联动，不发生信息割裂；
3. **安全物理隔离**：模拟数据 100% 本地闭环，严禁向券商或交易所发起实盘请求。

## Decision

### 1. 方案落地：三大核心 UI 锚点

#### ① 顶部工具栏全局分段切换胶囊 (`QuoteStage.tsx`)
- 位于顶部图表周期（1m/5m/1d）右侧操作区，紧挨「交易工作台」开关；
- 采用 Segmented Capsule 布局：
  - `[ ⚡ 实盘交易 ]`：深色质感；
  - `[ 🧪 模拟交易 (Demo) ]`：激活时呈高亮琥珀黄（Amber）；
- 点击模式持久化于 `localStorage`（`dshtrading:trade:mode`），切换为模拟盘时自动唤起交易面板。

#### ② 右侧下单面板联动 (`OrderPanel.tsx`)
- **标题栏标示**：右上角展示琥珀黄 `[🧪 模拟盘 (虚拟资金)]` 标签；
- **资金快捷重置**：右上角配备 `[↺ 重置模拟金]` 按钮，支持一键恢复 100,000 初始虚拟资金；
- **可用额度提示**：展示实时虚拟可用余额；
- **防错下单按钮**：主按钮自适应为 `[🧪 模拟买入 (ETH)]` / `[🧪 模拟卖出 (ETH)]`，外加虚线警告框。

#### ③ 底部资产抽屉联动 (`TradeDrawer.tsx`)
- 左侧 Tabs 前标明 `[🧪 模拟盘账本]`；
- 四大页签（当前持仓、活动委托、成交流水、账户余额）直接展示虚拟账户真实计算结果；
- 右侧增加快捷 `[↺ 重置模拟金]` 按钮。

### 2. 本地内存撮合引擎 (`paper-trading-store.ts`)

- 纯前端状态管理，以标的、方向、价格、数量为输入，立即按市价/现价模拟成交；
- 支持多币种与初始资金分配，维护实时未实现盈亏与历史流水；
- 数据物理隔离，不发送任何外部网络报单请求。

## Alternatives considered

<!-- agent-note-format: alternatives-not-recorded (pre-format Agent Note) -->
- **服务端模拟盘**：需要后端部署持久化撮合服务与数据库，增加网络通信开销与部署复杂度；落选，纯本地 localStorage 闭环具备零网络延迟和强私密性。

## Consequences

- 交易员可在同一界面无缝切换真实交易与模拟演练，降低试错风险；
- 模拟盘与实盘在视觉标签、按钮文案和配色上形成强防错屏障，杜绝误操作。
