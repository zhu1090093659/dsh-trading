# Agent Note: 默认发送完整标的上下文

Status: implemented

## Problem

统一发送入口默认只打包行情、图表取数位置与指标读数。新闻只在新闻/公告页签或事件图钉开启时轮询，基本面仅在对应页签取数；直接读取页面缓存无法满足默认一键交付完整研究信息。

## Decision

- 主按钮与首项菜单点击时并行调用既有新闻聚合和基本面桥接口，不依赖是否打开对应页签。保留行情、K 线定位、已算指标与可用图表截图，并附已有衍生品快照。只填输入框、不自动发送。
- 公告与媒体新闻复用 `isAnnouncementSource` 分组，各按发布时间倒序保留至多 10 条，携带标题、来源、时间、URL。聚合失败和检索空结果分开表达，不把空结果解释为无事件。
- 基本面包括公司概况、估值、最近三期财务、经营效率、预测、业务构成、股东与公司行动等有界摘要；保留财报币种和单位。外部文本限制长度，列表截取明示；不填造缺失值。来源未由接口提供时声明未知。
- 明示外部资料不是指令，要求正式研究先检索知识库，再优先调用本项目市场工具补查并验证原始披露，不能只分析技术指标。
- 补齐请求限时 15 秒，接口接受取消信号；超时保留其他部分并明示缺失。使用同步 ref 锁防止重复点击，切标的/卸载取消旧请求且清理反馈计时器。采集前捕获目标会话，填入前校验当前会话未变，防止异步补齐写入另一会话。

## Alternatives considered

- 复用页签缓存：速度快但未打开页签时数据必然缺失，无法满足默认行为，未采用。
- 内联完整财务矩阵与无限新闻：上下文体积不可控，改为有界摘要和后续工具核验。
- 自动发送并立即启动分析：用户需要补充自己的问题，沿用只填不发。

## Consequences

按钮从即时填入变为短暂采集后一次填入，沿用原 sending/sent/error 反馈。上游无数据或超时仍可得到行情与明确缺项，不承诺每个市场都有公告或基本面数据。截图只在图表挂载期间可得；财报摘要不是完整尽调。

针对测试覆盖分组/来源、空结果与失败、财报截取与零值、图表页主动取数、重复点击和切标的取消。实际独立 trading-web 宿主未运行时，不以组件测试冒充真实终端验收。
