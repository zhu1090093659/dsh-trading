# Agent Note: 宏观面板日历整周倒序（最新日期在最上）

Status: implemented

## Problem

2026-11-07 用户反馈宏观面板排反了：「近期的排在上面，远期的排在下面，最新日期的应该优先
显示」。截图（当天周六 11-07）首屏从周一 11-02 08:30 一路往下排，最新发布的条目要滚到底
才看得到。成因是 `MacroPanel` 自 2026-09-15 起按 `publishedAt` **升序**铺开整周，再用
「首屏锚定今天」把当天滚到顶部（见 [2026-09-15 锚定记录](2026-09-15-macro-panel-anchor-today.md)）：
顺序本身仍是旧的在上，锚定只是把视口挪到中段；那张截图的首屏停在列表顶部（11-02），说明
那次会话里锚定没有生效，观感就退回「旧数据占满首屏」。

同日用户裁决排序口径：整周严格倒序，本周尚未发生的预告也按日期从后往前排；不采用
「已公布倒序 + 未发生正序垫底」的分段排法。

## Decision

- 日历行按 `publishedAt` **降序**排序（`b.publishedAt.localeCompare(a.publishedAt)`），
  在地区过滤之后排序，跨日整体倒序、不按天分组。首屏即本周最新日期，越往下越早；本周
  尚未公布的条目（公布值 `--`）因日期最晚排在最前，是用户 2026-11-07 明确选择的口径。
- 「首屏锚定今天」整组移除：`calendarAnchorDate`、`localDateKeyOf`、`calListRef`、
  `anchoredRef`、rAF 滚动 effect 与行上的 `data-dshtrading-cal-date` 属性一并删除。倒序
  之后首屏天然是最新日期，锚定只是为补偿升序而存在的第二套机制，留着会与排序打架（打开
  面板先跳到中段，反而看不到最新）。
- 利率页签不动（保持上游顺序，体量级先行）。

## Alternatives considered

- **已公布倒序 + 未发生正序垫底**：首屏留给今天及更早的已公布数据，本周剩下的预告压到
  列表最下面。当次把两种排法都摆给用户，未采纳：日历是「本周日程」，还没发生的日程本身
  是最该先看到的信息，两段式排序还会在最早一条与明天之间留下断点。
- **保留锚定、只翻转排序**：排序与滚动两套机制互相矛盾（打开先停在中段，最新反而要往上
  滚），且锚定只为升序兜底，属重复机制；YAGNI。
- **升序 + 今天高亮/分隔条**：2026-09-15 已否决（视觉噪音），而用户这次要的是顺序本身。

## Consequences

- 打开宏观面板第一屏就是本周最新日期（含未发生预告），往下按时间递减阅读。
- 移除约 40 行滚动校正代码与两个导出纯函数；`macro-panel.smoke.test.tsx` 的锚定用例整体
  换成渲染级顺序断言（上游乱序到达 → 跨日倒序；地区过滤后仍倒序）。用例做过变异核对：
  改回升序即红。
- 面板不再自动定位到今天：当天数据由排序自然落在「更晚日期之下、更早日期之上」，找当天
  公布值按时间往下找即可。
