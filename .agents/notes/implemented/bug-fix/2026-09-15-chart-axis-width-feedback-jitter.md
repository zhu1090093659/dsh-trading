# Agent Note: 行情图蜡烛持续抖动——右轴百分比标签宽度与绘图区宽度互馈

Status: implemented

## Problem

用户报告（2026-09-15，承接同日 [主图读数行行数跳变](./2026-09-15-quote-readout-row-height-jitter.md)
修复后复测）：「没有解决，在无操作时仍然疯狂抖动」。补充判据（同轮问答）：

- 抖的是**整根蜡烛**（重排 + 重定标），不是读数行；
- **鼠标停在图表内任意 K 线上就不抖**，移出图表就抖；
- **关掉底栏 KDAS（主图指标全关）仍然抖** —— 排除读数行/指标读数链路；
- **折叠左侧自选、折叠或拖拽右侧边栏宽度就彻底不抖** —— 指向「宽度」这条链路。

headless Chrome（trading-web 宿主 55001，选中 `cn:002714.SZ` 牧原股份 日K、6 条 KDAS）
在页面内直接改图表容器宽度扫描，复现：**容器宽 625/630 px 时同一张图在三个状态间无限
跳**：

| 状态 | 可视区 from | 左轴宽 | 右轴宽 | 绘图区画布宽 |
| --- | --- | --- | --- | --- |
| A | 695.00 | 54 | 66 | 768 |
| B | 694.11 | 54 | 58 | 780 |
| C | 695.67 | 54 | 72 | 759 |

即右轴在 5/6/7 字符标签宽度（58↔66↔72 px）之间反复，绘图区宽度随之 ±21 px，蜡烛
按新绘图区重排重定标 —— 肉眼就是「疯狂抖动 + 只有 K 线在抖」。改宽度即离开临界点，
所以折叠/拖拽都能"治好"。

## Root Cause

lightweight-charts 的价格轴宽度 = **当前刻度标签里最宽的那一条**（+ 轴内边距），而绘图区
宽度 = 容器宽 - 左轴 - 右轴。于是存在结构上的正反馈：

```
容器宽固定 → 轴宽 = f(最宽刻度标签) → 绘图区宽 → 可视 K 线根数/位置 → 自缩放价格区间
          → 刻度取值 → 标签文本 → 轴宽 …
```

lwc 自带的左轴（价位标签）在这条链上基本稳定（价位量级不变时标签字符数不变），本仓右侧
「相对涨跌幅」轴把这条链打断了又接上：

1. 标签文本 = `(price - ref)/ref*100` 两位小数 + `%`，**正数不带正号**，量级跨 10/100
   各差一个字符（`8.40%` 5 字符 / `16.02%` 6 / `-21.81%` 7）；
2. 参考价 `ref` 取**可视区最左一根收盘** —— 它本身是可视区的函数。

所以可视区一动，右轴标签的最大字符数就可能在 5/6/7 之间翻，轴宽随之翻，绘图区宽随之翻，
可视区又动 —— 收敛不了。上表 A/B 两态 ref 相同（`ceil(695.00)=ceil(694.11)=695`）却宽度
不同，说明**驱动量是刻度集合本身**（最左一根是否被算进自缩放），而非 ref 的取值。

## Decision

新增纯函数模块 `packages/client-ui-trading/src/client/axis-width.ts`，给右轴一个**与可视区
无关**的宽度下限（lwc `rightPriceScale.minimumWidth`）：

- `percentLabel(value, ref)`：百分比标签的唯一口径，右轴 formatter 与宽度下限共用（避免两份
  实现漂移后下限静默偏窄）；
- `percentLabelCandidates({minPrice, maxPrice, minClose, maxClose})`：按当前数据给出可能出现的
  两个最宽百分比标签——正向极值在「参考价取最小收盘、价格取轴范围上界」时取到，负向极值在
  「参考价取最大收盘、价格取轴范围下界」时取到（可视区口径下参考价必落在收盘极值区间内；
  2026-10-27 起五日级别改传固定锚点 `ref`，候选按锚点直接算，见
  [五日级别右轴锚点](./2026-10-27-five-day-percent-axis-anchor.md)）。轴范围上/下界
  按 `AXIS_SCALE_MARGIN`（= TvChart 的 `scaleMargins` 0.08，同一常量来源）各外扩
  `区间×m/(1−2m)`——留白会把顶端刻度撑到数据最高价之上，不外扩就会少算一个字符；
- `axisMinimumWidth(labels)`：用 canvas `measureText` 取最宽标签的浏览器文本宽度 +
  `AXIS_LABEL_MARGIN`（lwc 轴内边距实测 26.4–28.1 px，取 32 保守值；无 DOM 环境回 0，
  调用方据此跳过 `applyOptions`）；
- `TvChart` 的镜像包络 effect（已有 bars ∪ mainOverlays 遍历）顺带记录价格/收盘极值，算下限并
  `chart.applyOptions({ rightPriceScale: { minimumWidth } })`，值变了才调用 —— 下限只随数据变化。

轴字体同时提为模块常量 `AXIS_FONT_SIZE/AXIS_FONT_FAMILY`，`getChartThemeOptions` 与测量共用
（字串与 10.5 px 原值一致，视觉不变）。

## 评审后续修复（2026-09-15）

同日 review-spd（三个提交）对本修复提出两条，已同变更修掉：

- **下界漏算轴留白**：候选标签原只按数据极值算，没算 `scaleMargins`（两轴各 0.08）把可见价格
  范围撑出数据区间的部分——轴范围 = 数据区间/(1−2m)，顶端刻度可比最高价高约 9.52%·区间，于是
  真实最大标签可达候选值的 1.0952 倍。数据区间恰好落在量级边界下方约 9% 时（如最大涨幅 9.5%），
  真实标签已是 `10.40%`（6 字符）而候选只给 `9.50%`（5 字符）；`AXIS_LABEL_MARGIN` 相对实测
  内边距的余量（3.9–5.6 px）小于一个等宽字符（10.5 px 字号约 6.3 px），下限压不住自然轴宽，
  抖动在这一档标的上仍有回归路径。修法：候选先按 `span·m/(1−2m)` 外扩上下界，
  `AXIS_SCALE_MARGIN` 常量与 TvChart 四处 `scaleMargins` 共用同一来源。
- **标签口径两份实现**：候选文本与 `mirrorPercentFormat` 各写一份百分比格式化，任何一侧改动都
  会静默让下限偏窄且无测试可发现。抽出 `percentLabel` 供两侧共用。

回归：`test/axis-width.test.ts` 新增「最大涨幅 9.5% → 候选必须覆盖 10.40%」与 `percentLabel`
参考价守卫用例（9 例）。

## Alternatives considered

- **给 formatter 补空格定宽**：轴宽确实恒定，但最后一个价位徽标、十字光标标签共用同一
  priceFormat，红/黑底框会多出一截左侧空白，视觉回退明显。
- **静态下限（如固定 88 px）**：对任何标的都不抖，但常驻多占 16–30 px 绘图区宽，且
  极端百分比（±10000% 级）仍会顶破。
- **改参考价来源（用最后一根收盘等）不依赖可视区**：上表 A/B 两态 ref 相同仍翻宽，说明
  刻度集合才是驱动量，换 ref 不解决。
- **下限按可视区极值算并单调只增**：能收敛（单调有界）但语义更绕、多一份状态；数据界已经够保守。
- **把右轴标签改画在 canvas 上自绘**：等于重做镜像轴，代价远超本次缺陷。

## Consequences

- 复现宽度不再抖：修复前 600–1300 px（步长 5）扫描有 2 个抖动宽度（625/630），修复后
  **0 个**；600–700 px 步长 1 的细扫同样 0 个；625/630 两处只剩单一稳定状态
  （牧原股份右轴恒定 78 px，`minimumWidth` 77）。
- 右轴比此前「刚好够」时宽约 10–20 px（牧原股份：自然宽 58–72 → 恒定 78），换绘图区
  约 1% 的宽度；标签本身不变，徽标/十字标签外观不变。
- 下限是**数据相关**量：换标的/换周期/数据增长导致价格极值变化时，右轴宽度会随之一次性
  变化（非抖动，与左轴随量级变化同性质）。左轴未加下限（本次实测恒 54 px，未观察到翻转）；
  若将来左轴也出现标签字符数随可视区翻转，同一 helper 可直接复用。
- `AXIS_LABEL_MARGIN = 32` 依赖 lwc 轴内边距（实测 2026-09-15 / 5.2.1）；升级 lwc 后若
  该内边距变小，下限偏保守（多几像素留白）无碍，变大则需同步该常量。
- 验证：`packages/client-ui-trading` 406 用例全绿（新增 `test/axis-width.test.ts` 5 例）；
  `tsdown` 重建 `lib/client.js`（与 profile 内 file: 副本同 inode/md5，运行中宿主按盘读取）。
  宿主实机复测待用户刷新窗口后确认。
- 同日两份记录都叫「图表抖动」但根因不同：本记录是**轴宽 ↔ 绘图区宽**反馈（不悬停也抖、
  与悬停位置无关，靠指针位置/容器宽度改变临界点），
  [读数行行数跳变](./2026-09-15-quote-readout-row-height-jitter.md) 是**读数行行数 → 容器高度**
  跳变（悬停跨锚点才跳）。
