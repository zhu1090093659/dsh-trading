# 每周交易计划（weekly-trading-plan）

把「消息面 + 台账持仓 + 知识库 + 本周复盘」合成一份**下周可执行的双向预案**，而不是行情预测。计划的价值在纪律：每条意向都写清为什么做、期待看到什么、什么事实出现就认错、错了第一步做什么。

> 副本约定：本技能同时存在于工作区项目根 `.agents/skills/weekly-trading-plan/`（live 副本，随会话即时生效）与本仓库 `.agents/skills/weekly-trading-plan/`（打包副本，经 `scripts/sync-skills.mjs` 同步进 `packages/base/assets/skills/`）。**改动必须两处一致**；打包副本的脚本资源随目录整体分发。

## 1. 何时用 / 何时不用

**用**：用户要求制定本周/下周交易计划、周度作战计划、把复盘与持仓消息合成为计划；周末例行生成；周中行情推翻上周计划需要重订。
**不用**：单票深度研究（走 `company-analysis` / `crypto-instrument-analysis`，或委派 `researcher_subagent`）；盘中临时决策（走 `reports/trading_system_v1.md` 六道闸门 + 候选登记）；纯行情/持仓查询（直接答，不需要计划仪式）。

## 2. 交易模式 × 交易策略 × KDAS（计划的骨架）

每条意向必须先落到「**模式 → 策略 → 执行层**」三层，缺一层的意向不得进计划。权威定义：`reports/trading_system_v1.md`（§1 模式 / §3 G3 / §4 分市场策略）。

### 2.1 模式层：A 主仓 / B 辅线

| | 模式 A 基本面中长线 | 模式 B A股短线题材 |
|---|---|---|
| 赚钱逻辑 | 稀缺性预期差（供给约束 / 护城河 / 牌照 / 网络效应 / 出清后幸存） | 情绪周期内的题材轮动价差 |
| 时间尺度 | 月—年 | 日—周 |
| 退出依据 | 核心假设被事实证伪 | 预设失效位 / 时间窗失效 |
| 加仓依据 | **重新满足预设条件** | **重新满足预设条件** |

- 判定口诀：**写不出「稀缺性来源」的，不是 A；不在情绪周期「成→住」段的，不是 B。**
- 每条意向显式标注 `模式 A` 或 `模式 B`；两套纪律不互通（见 §6 红线 3）：A 不因短线走强升级，B 不用 A 的假设兜底、不挤占 A 的资金与风险预算。
- 模式 B 仓位上限 = 总资产 30%（用户 2026-09-11 确定）；**单笔风险预算未定 → 只列前置条件与观察项，不出仓位方案**。

### 2.2 策略层：分市场策略

| 市场 | 当前策略口径 | 计划里必须写清 |
|---|---|---|
| us | 成熟蓝筹走趋势：持有 + KDAS 执行时机，不短炒 | 是否已指定关键日（PURR / AAPL / GOOGL / QQQM 需先指定） |
| hk | 外资态度第一窗口、弹性大于 A 股；融资账户按总敞口计 | AH 溢价、沽空、杠杆敞口 |
| cn 主仓 | 假设持有 + KDAS 分层买点加仓 | 集中度越线项（越线标的禁止同向加仓） |
| cn 辅线 | 涨停池 + 集合竞价强弱 + 题材梯队，只做「成→住」段 | 情绪周期位置、开仓前置条件是否满足 |
| crypto | 无持仓时仅作信号源；建仓须独立假设 + 独立风险预算 | 24/7 无收盘确认 → 纪律改用 UTC 日界 |

- **策略名册现状**：先调 `strategy_list` 读实际可用项（实测 2026-09-13：6 个内置范式均为 tombstone 状态、无自定义策略）。名册为空时策略层以上表与 `trading_system_v1.md` §4 为准，**不得引用名册里不存在的策略**。
- 需要启用或新增策略时先问用户：恢复内置用 `strategy_reset`，新增用 `strategy_author`；新规则必须先 `strategy_backtest` 验证（标注参数与样本区间）才可作为纪律线索；**回测只作规则证据，不作收益或方向预测**。
- 深度个股策略结论委派 `researcher_subagent` / `company-analysis` / `crypto-instrument-analysis`；委托结论必须与行情、台账、公告交叉核验后才进计划。

### 2.3 执行层：KDAS 关键日期均价线

- **是什么**：自定义指标 `kdas`——自关键日起算的 Anchored VWAP（`TP=(H+L+C)/3`，按成交量加权），最多 8 条，读数 3 位小数；默认含当日未完成日 K（该根量能仍在累积，读数随盘中变动）。
- **关键日现场值**：`indicator_list` → `custom[kdas].symbolParams["<market>:<symbol>"]` 是唯一权威；**不要引用文档或记忆里的旧关键日**（关键日随行情更新，当前已配 6 个标的：00700.HK / 02714.HK / 002714.SZ / 513050.SH / 159869.SZ / 001201.SZ）。
- **复算**（把 G3 变成可核对的数字，别凭感觉）：
  ```bash
  # 脚本位于本技能目录 scripts/kdas.py（按 skill_resources 的 Base directory 拼绝对路径）
  python3 <skill 目录>/scripts/kdas.py \
    --market cn --symbol 002714.SZ --keys 20250821,20240924,20260905,20260825,20260317,20260625,20260512
  ```
  港股加 `--klines-file <futu 日 K JSON>`（图表走 futu；腾讯公开源复算实测同值，但复权口径可能不同）；需要只算已完成日 K 时加 `--drop-last`（保守开关）。脚本与指标同算法、同锚定口径（含「openTime 的 UTC 日」判定——港股日 K 会因此比名义关键日晚一个交易日锚定），锚点被截断或关键日未生效时 **fail-closed 不出数**。
- **买点分层（G3 判定，`trading_system_v1.md` §3 G3）**：
  1. **最佳买点**：自然寻底末端，低位首次突破并站稳关键日 KDAS（强弱分界线 / 最后一两根线）。
  2. **次优买点**：突破后回踩近端 KDAS 不破，旧压力转新支撑，收盘确认。
  3. **禁买**：右侧趋势内追高——价格已远离真正买点。错过后等下一次回踩或新接力结构，**不做补偿性追单**。
- **纪律角色**：KDAS 只做执行层与趋势阶段判断；破位只触发「复核假设」，不自动清仓（清仓由假设证伪决定）。
- **未指定关键日的标的**（当前 PURR / AAPL / GOOGL / QQQM / HYPE）→ G3 判「不可判」，列入计划待办并与用户确认，**不得自行指定关键日、不得自行写指标参数**。
- **参数红线**：`indicator_activate` 带 `market + symbol` 却不传 `paramsJson`，会用全局默认（全 0）**覆盖该标的的 per-symbol 关键日**（2026-09-08 实证）——本流程只读关键日。

## 3. 输入事实源（先取证，再计划）

| # | 来源 | 取数方式 | 用途 | 取不到时 |
|---|---|---|---|---|
| 1 | 统一资产台账 | `holdings_list`（正式 + 待确认区） | 持仓、成本、账户、集中度 | 台账空 → 说明并只做观察计划 |
| 2 | 账户真值（活钱敏感时） | `cn/hk/us_get_balance`、`crypto_get_balance/positions`、`futures_get_balance/positions` | 与台账对账、算现金与可用风险预算 | `TRADING_NOT_IMPLEMENTED` = 不可用，**不是零余额**，如实标注 |
| 3 | 本周复盘 | 优先用已产出的复盘（周六 10:00 周总结、周六 18:01 美股复盘+管道周度、周一 08:30 牧原周跟踪、每日巡检/每日收盘复盘）；`grep` 当月 `.trading-journal/agent/YYYY-MM.md` | 本周涨跌、量能、事件、假设检验状态 | 复盘缺失/任务失败 → 按 §7 降级自算并落盘 `reports/weekly_reviews/`，声明降级理由 |
| 4 | 市场消息与公告 | `cn_get_news` / `hk_get_news`（含公告，公告优先）/ `us_get_news` / `crypto_get_news`；宏观用 `flash_list`、`news_search`；**下周事件日历**用 `econ_calendar` | 消息面与下周催化剂/风险时点 | 无独立公告工具时用新闻面 + 官方披露，缺口如实列 |
| 5 | 核查事实库 | `grep -rn <关键词> facts/`（rg 不在 PATH 时） | 已核实的原子事实（带来源日期与状态） | 无命中如实写 |
| 6 | 知识库 | `knowledge_graph` → `knowledge_search {cluster}` → `knowledge_get` | 观点线索；引用须带 `kc_` id + 卡片 `updatedAt` + 素材发布日 | 无命中写「知识库无相关沉淀」 |
| 7 | 假设与纪律档案 | `reports/hypothesis_tracking/*.md`、持仓 thesis（如 `reports/purr_hype_holding_thesis.md`）、`reports/trading_system_v1.md`（模式 A/B + 六道闸门）、`reports/macro_pipeline_state.json` | 判定假设状态、给计划套纪律 | 档案缺失 → 先补基线再出计划 |

**纪律**：卡片是「别人观点的结构化转述」，只作线索，不替代原始披露；宏观/政策类卡片过期即降权。任一来源取不到，写「数据缺口」，不得用记忆补数。

## 4. 标准流程（S1–S7）

- **S1 台账与资金分层**：读台账 → 按 §2.1 给每个标的与每条候选意向归入模式 A（全市场基本面中长线）/ 模式 B（A股短线题材），未归类的不得进入后续步骤；算各标的占总资产比重、单账户集中度、现金与融资敞口；**列出越线项**（越线标的禁止同向加仓）。
- **S2 本周复盘取证**：按 §3 第 3 行取；逐标的给出本周涨跌幅、周线状态、量能对比、本周事件、相对关键位的距离（关键日 KDAS 用 §2.3 脚本复算、MA、前高前低）。**深度个股结论不在此处展开**（委派深研），此处只做组合层快照。
- **S3 假设面板**：逐条对照假设档案的失效条件与验证信号，判定**验证中 / 承压 / 已证伪**，写出「下一验证点 + 预计日期」。
  - 到期检查点（如假设档案里的 T+1 周表格）→ 按 append-only 回填/追加检验记录，**不改历史行**。
  - 判定「已证伪」→ 计划第一动作是**停旧策略、降风险**，不摊平、不换叙事。
- **S4 消息面与下周日历**：本周该市场最重要 1–3 条消息/公告（标来源与时间，公告优先）；下周事件日历（议息、经济数据、财报、解禁、拍卖）逐日列出，区分「已定价的坐标」与「可能改变预期的变量」。
- **S5 知识库与事实召回**：先 `facts/`，再图谱/检索；引用卡片带 id 与时间戳；与当前事实冲突的过期卡片降权并说明。
- **S6 计划生成**：先定模式与策略口径（§2.1 / §2.2），再按模式 A / B 分层，逐条意向过六道闸门（G1 一句话可证伪假设 / G2 预期差定位 / G3 买点分层与关键日 / G4 环境信号清单 / G5 资金分层与集中度 / G6 冷静期 + dry-run + 留痕）。**加仓必须重新满足预设条件**，不因「上周已持有」自动授权。
- **S7 落盘与留痕**：写计划文件（§5 模板），追加一条 agent 轨日志（格式按 `trading-notes-setup`：引用标题 + 一句话结论，不贴全文）。

**可选复核**：计划涉及新开仓、加仓或集中度调整时，可在定稿前委派 `risk_reviewer_subagent` 做敞口与预案复核；**其结论必须与行情、台账、公告交叉核验后再采纳**，冲突时在计划中给出裁决理由，不整段照抄。

## 5. 输出契约

交付给用户的内容按**三层**组织，并标注每条来源（`委托获取` / `本会话核实`）：

1. **事实层**：台账与资金、本周行情与量能、公告与消息、已核实事实（按证据契约三字段落账：来源等级 / 判定 / 锚点；来源 + 时间 + 币种/单位；卡片引用带 `kc_` id 与 `updatedAt`）。
2. **假设层**：本周计划所依据的核心假设（一句话、可证伪）+ 各假设档案的当前状态。
3. **预案层**：假设成立怎么做 / 被证伪怎么做（双向预案）+ 再入场条件 + 失效条件。

计划文件落点与固定小节：

```
reports/weekly_plans/YYYY-Www.md        # 计划周 = 周一至周五（ISO 周编号）；目录不存在则创建
```

```markdown
# 每周交易计划 · YYYY-Www（计划周 YYYY-MM-DD ~ YYYY-MM-DD）

> 生成：YYYY-MM-DD HH:MM（本地）｜台账 revision / 取数时点｜复盘来源：<任务名 + 日期 / 降级自算>
> 性质：纪律文件，不是预测，不构成投资建议。

## 1. 一句话核心假设（可证伪）
## 2. 组合状态
   持仓表（标的/模式/账户/成本→现价/占比）｜现金与融资｜越线项（禁止同向加仓）
## 3. 假设面板
   | 编号 | 一句话假设 | 本周判定（验证中/承压/证伪） | 下一验证点 | 预计日期 |
## 4. 分市场计划
   ### 模式 A 主仓（crypto / us / cn / hk 分列）
      每条：模式 A/B｜策略口径（§2.2）｜G1 假设｜G2 预期差定位｜G3 KDAS 买点分层（关键日 + 复算读数）｜G4 环境信号｜G5 预算与集中度｜G6 执行路径（冷静期/dry-run）｜锚点（工具+参数+数值+数据时间 / 公告 / facts 条目 / 卡片 id）｜判定（supported/contradicted/mixed/insufficient）
      双向预案：假设成立 → …｜被证伪 → 先停旧策略并降风险 → …｜再入场条件：…
   ### 模式 B 辅线（A股短线题材）
      当前情绪周期位置判定；是否具备开仓前置条件（含用户未定的单笔风险预算）
## 5. 下周事件日历（逐日：议息/数据/财报/解禁/拍卖）
## 6. 待用户决策（未定参数、需授权项、需澄清的口径）
## 7. 数据来源、时间戳与缺口（含降级说明）
```

**写作规则**：不预测点位与方向，只写假设与触发事实；每条意向必须能回答「什么事实会证明我错了」；不能回答的，不得进计划。

## 6. 红线（与项目级规则一致）

1. **不预测，只假设**：禁止给价格目标与方向预测；一致预期只作「市场已定价的坐标」，并标数据日期。
2. **不引用卖方评级与目标价**（评级、目标价一律不进计划，也不作旁证）。
3. **两套纪律不互通**：辅线仓位不得用主仓假设兜底，主仓不得因短线走强而升级；资金分层，辅线不挤占主仓预算。
4. **未定参数不代填**：A股辅线单笔风险预算未由用户确定前，**不出具体仓位方案**，只列前置条件与观察项。
5. **加仓重过闸门**：任何加仓都要重新满足预设条件；越线标的禁止同向加仓。
6. **只读分析**：本技能不下单、不改台账（台账增删由用户在资产面板完成）；订单默认 dry-run，实盘必须用户显式授权并走审批闸门。
7. **留痕**：计划产出与任何后续操作按双轨 append-only 记录；dry-run 显式标注。
8. **不越权改参数**：关键日、策略名册、指标参数都属于用户；计划只读，改动须先确认。
9. **免责与证据**：数字标来源/时间/币种/单位；区分事实、推断、情景；每条意向与结论按证据契约三字段（来源等级 / 判定 / 锚点）落账，写不出锚点的记 `insufficient` 并移入观察项而非结论；结论不构成投资建议。

## 7. 复盘缺失时的降级路径

本周复盘产物不可得（定时任务失败、非交易日执行、新会话无上下文）时：

1. **声明降级**：在计划头部写明「复盘来源：降级自算」及原因；不假装有复盘。
2. **自算组合层快照**并落盘 `reports/weekly_reviews/YYYY-Www.md`（目录不存在则创建）：各持仓周涨跌幅与周线状态、量能对比、关键技术位距离、本周公告/新闻要点、假设检验读数。**只做组合层**，深度个股研究委派 `researcher_subagent` 或走 `company-analysis`。
3. **补齐假设检验**：从当月 agent 轨日志提取每日巡检的 S/M/G/H 读数，填 `hypothesis_tracking` 到期检查点。
4. **标注缺口**：缺哪一项就写哪一项，后续补上时以新条目追加，不改历史结论。

## 8. 时效与修订

- 计划周内行情与假设冲突时：**先停旧策略、降低风险**，再重订计划；修订以追加方式写入同一文件末尾（`## 修订记录`：时间 / 触发 / 改了什么 / 依据），不静默改写历史结论。
- 跨周：新建下一周文件，与上周文件并存，形成可回检序列（结果回检是知识库沉淀的素材，见 `knowledge-curation`）。
- 新的可复用结论 → 先 `knowledge_search` 查重，再按 `knowledge_curation` 与 `reports/knowledge_taxonomy.md` 的受控词表建议用户入库。
