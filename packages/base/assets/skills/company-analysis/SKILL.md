## 范围边界

不要把本 Skill 用于纯技术分析、纯宏观分析或纯 ETF 成分比较，除非用户明确要求把它们纳入公司分析。

## 核心原则

### 先审计证据，再给结论

在涉及事实判断、投资逻辑、风险判断、目标价、估值、公司质量评价时，必须先做证据审计，不要直接跳到结论。

每个关键判断都要拆成可验证命题，并标注命题类型：

| 类型 | 含义 | 示例 |
|---|---|---|
| 事实命题 | 可直接用数据、公告、财报验证 | 公司自由现金流连续三年为正 |
| 因果命题 | A 是否导致 B | 股价下跌是否由基本面恶化导致 |
| 意图命题 | 管理层、机构、股东的动机判断 | 回购是否为了稳定股价 |
| 预测命题 | 对未来业绩、估值、风险的判断 | 未来两年利润率是否改善 |
| 价值判断 | 是否值得买、是否便宜、是否优秀 | 当前估值是否有吸引力 |

### 信源分级

优先追溯原始来源。引用社媒、论坛、视频、二手文章时，只能作为线索，不能作为最终证据。

| 等级 | 信源 | 使用规则 |
|---|---|---|
| S | 财报、年报、10-K/20-F/10-Q、招股书、交易所公告、监管文件、公司公告、公司 IR、指数公司规则、原始数据、原始论文/代码 | 可作为核心证据 |
| A | 官方统计、交易所数据、公司电话会纪要、同花顺金融数据服务 (HiThink / iFinD / fuyao)、Wind 万得金融数据、主流财经数据库、权威金融数据商、权威行业协会、评级机构、头部媒体原始采访 | 可作为强证据（含财务报表、集合竞价、涨跌停池、龙虎榜席位与概念分类） |
| B | 券商研报、行业报告、第三方数据库、媒体深度报道 | 可作为辅助证据，需交叉验证；研报观点、目标价和盈利预测不能替代原始披露 |
| C | 财经自媒体、新闻聚合、二手摘要、未经完整披露的研报摘录 | 只能辅助理解，不能单独定论 |
| D | 社交媒体、论坛、Reddit、雪球评论、视频博主、传闻 | 只能作为线索 |
| E | 无出处截图、AI 摘要、无法追溯来源的信息 | 不作为证据 |

### 防污染规则

- 不把股价下跌自动解释为“错杀”。
- 不把估值低自动解释为“便宜”。
- 不把营收增长自动解释为“成长性好”。
- 不把管理层口号、战略愿景、媒体通稿当成兑现能力。
- 不把单一季度数据外推成长期趋势。
- 不把研报目标价当作事实。
- 不把“当前现实很好”自动解释为还可以买；必须判断价格是否已经反映甚至过度反映现实。
- 不把“当前现实很差”自动解释为不能买；对周期股要判断预期是否已经开始改善。
- 不把远期预期、政策口径、期货升水、订单展望等直接写成已经兑现的现实。
- 不为了形成完整结论而编造缺失数据。
- 必须主动寻找最强反方证据，并说明它是否真正削弱投资逻辑。

### 预期与现实框架

公司分析必须融入 `/Users/zcl/cowork/trading_journal/rules/fundamental_analysis_framework.md` 的底层框架。若该文件可读，开始分析前先读取；若不可读，也必须按以下稳定规则执行。

核心口诀：大部分基本面交易都是买预期、卖现实。拿到基本面信息后不能只判断“好不好”，还要判断当前价格反映的是过去现实、当前现实，还是未来预期；以及反映不够、反映刚好，还是反映过度。

先把标的归入以下三类之一，并在报告中显式说明：

| 模式 | 适用对象 | 核心买点 | 核心卖点 | 常见误区 |
|---|---|---|---|---|
| 模式一：买预期、卖现实 | 周期股、商品链、强周期制造、政策/景气反转型公司 | 现实仍弱但未来基本面边际改善，且价格尚未充分反映 | 利润兑现、报表好看、市场集中上修、估值进入乐观区间 | 等现实完全好转才买，或把预期当成已实现利润 |
| 模式二：买现实、买预期 | 少数持续高增长公司、现实强且未来可能更强的公司 | 现实强，同时未来空间继续打开且价格未过度反映 | 未来增速下修、估值过度透支、竞争格局恶化 | 把普通成长股误判成长期复利资产 |
| 模式三：买现实、卖现实 | 红利/现金流型、成熟稳定公司 | 现实现金流和分红稳定，估值偏低 | 估值偏高、分红覆盖恶化、有人强行讲新故事 | 把稳定现金流公司包装成高成长想象空间 |

每次分析都必须回答三个问题：

| 问题 | 目的 |
|---|---|
| 当前基本面是强还是弱？ | 区分已发生事实和经营现实 |
| 这个强度是否已经反映在价格里？ | 区分便宜、合理、过度定价和价值陷阱 |
| 未来基本面会变得更强还是更弱？ | 决定是买预期、买现实、卖现实还是等待 |

写结论时必须区分：

| 层次 | 含义 | 写法要求 |
|---|---|---|
| 现实 | 已发生的财报、经营、现金流、订单、价格、政策事实 | 用原始披露或权威数据证明 |
| 预期 | 未来利润、价格、需求、成本、政策、估值修复 | 标注验证条件和失效条件 |
| 定价 | 股价/估值是否已经反映现实或预期 | 结合估值、走势、资金、情绪和同业比较判断 |
| 动作 | 建仓、加仓、减仓、等待、卖出 | 必须对应所处模式和预期-现实阶段 |

### 公司类型识别与分析路由

公司类型必须先按主导价值来源识别，再决定分析模式；不能只在估值环节临时选择 PE、PB 或 PS。标准版和深度版开始分析前先读取 `references/company-type-analysis.md`；快速版只要问题涉及估值、公司质量、成长、现金流、周期、困境或事件，也必须读取相关类型章节。

分类时区分四个维度：主导价值来源、商业经济特征、公司当前状态、市场定价/交易模式。`成长`、`价值`、`周期`不是互斥的同层标签；“价值”通常是价格相对内在价值的状态，不能单独替代商业类型。

每次报告必须明确：

| 字段 | 要求 |
|---|---|
| 主类型 | 只选一个，用于决定问题路由、评分权重和主估值方法 |
| 次类型 | 可选 0–2 个，只补充检查项，不覆盖主类型 |
| 当前状态 | 高速扩张、成熟、周期底部/上行/顶部、经营恶化、反转、事件等待等 |
| 主导价值来源 | 增长再投资、稳定 FCF/股息、周期价差、资产重估、金融资产负债、修复、里程碑或事件概率 |
| 分类置信度 | 高/中/低；列出最强替代分类和反证 |

若不同分部经济性质显著不同，按分部分类并使用 SOTP；仍需指出当前对市值影响最大的主类型。若公司类型正在迁移，必须同步切换证据重点、评分权重、估值场景、风险和动作纪律。

### 周期股强制跨周期校准

当公司利润主要由外生价格、销量/产量和单位成本共同驱动，或用户提到周期、景气反转、商品价格、运价、猪价、金属价格、存储价格等变量时，先读取 `references/cyclical-company-analysis.md`，再进入估值与结论。

周期股报告必须完成以下门禁：

1. 用官方、行业或公司证据定义周期边界；覆盖最近两个完整周期或可比上行段。当前周期未完成或历史不足时，明确说明，不强行拼成两个完整周期。
2. 横向比较行业价格与供给、公司销量/产量、单位成本、价本差、归母利润、CFO/FCF、股价、市值、PB 及股价相对利润的领先/滞后。默认 3–5 年范围在此失效。
3. 把冲击型超级周期与可重复的正常周期分开；把月度/现货峰值与全年可持续均价分开。两者都不能直接进入基准场景。
4. 建立“有效销量或产量 × 单位量 × 价格成本差”的机械敏感性，再用历史转化率校准到归母利润，并列出期间费用、少数股东、内部抵销、存货节奏、税费等调整项。
5. 先把机构一致预期放入场景坐标，再命名场景。若所谓“牛市”已落在一致预期内，改名为弱修复或正常上行，并另设有明确条件的强周期与冲击尾部。
6. 从当前股价或市值反推市场隐含的可持续价差、利润和持续期，判断市场已经交易到哪一档，而不是只做正向目标价。
7. 区分“周期利润能力”和“单一年度预测”；禁止把峰值利润与高景气高估值倍数同时使用。
8. 用历史样本测量股价对行业价格、供给拐点、季度转盈和利润峰值的领先/滞后；不要把固定领先月数写成普遍规律。
9. 把“研究层面的预期试错候选”与“可执行交易计划”分开。前者不自动授权下单；后者仍需触发价、委托价、数量、有效期、失效和买回条件。
10. A/H 或双重上市先估统一经济价值，再分别解释流动性、持有人结构、税费、汇率、可转换性等结构性折溢价。

## 默认输出风格

- 使用简体中文。
- 最终报告默认以 HTML 呈现。标准交付是完整单文件 HTML：`<!doctype html>`、`<html lang="zh-CN">`、`<head>`、内联 `<style>`、`<body>`。如果聊天环境不适合渲染完整页面，也必须输出可直接保存为 `.html` 的 HTML 代码块，不使用 Markdown 标题、Markdown 表格或 Markdown 列表作为报告主体。
- 模仿专业卖方/买方研报风格：克制、清晰、证据密集，使用封面摘要、关键结论卡片、数据表、图表区块、脚注和来源清单；不要写成自媒体长文或营销页。
- 高信息密度，减少空话。
- 优先用 HTML `<table>` 呈现结构化判断；表格必须有 `<thead>`、`<tbody>`，必要时加 `<caption>` 或表下注释。
- 不使用 emoji，也不要使用表情符号、装饰性 pictogram、彩色符号图标来表达结论。状态只能用文字、颜色、边框、标签或表格字段表达。
- 图、表、文并茂：标准版至少包含 2-4 个 `<figure>` 图表区块。一个图表通常覆盖股价/估值位置，其他图表必须按主类型切换：成长看增长、ROIC 与 FCF；现金流型看 FCF、分红和杠杆；周期看供需、价格、成本和价差；资产型看 NAV 与折价；金融看 ROE、资产质量和资本约束；困境看现金跑道和债务到期；前盈利看里程碑和稀释；事件驱动看概率树、时间表和收益损失比。没有真实图片时，用 HTML/CSS 条形图、矩阵、时间序列表或可替换的 `<img>` 占位表达；如使用图片，优先使用来源可追溯的 PNG/JPEG 或本地生成图，并在 `<figcaption>` 标注数据口径。
- 样式使用内联 CSS，不依赖外部 CSS、JS、字体 CDN 或远程图标库。视觉应偏专业研报：白底、深灰文字、细分割线、克制强调色、适度留白，避免紫蓝渐变、过度圆角、卡片堆砌和模板化 Hero。
- 投资结论必须区分：事实、推断、假设、风险、个人适配性。

## 工作流

### 1. 明确分析对象

尽量从用户输入中自动识别：

| 字段 | 示例 |
|---|---|
| 公司名称 | 腾讯、英伟达、富途、PURR |
| 股票代码/市场 | 0700.HK、NVDA、FUTU、A 股代码 |
| 分析目的 | 是否值得买、为何下跌、财报复盘、估值对比、建仓计划 |
| 用户视角 | 短线/中线/长线，已有仓位，是否愿意接货 |
| 时间范围 | 最近财报、近 3 年、近 10 年、未来 12 个月 |
| 输出深度 | 快速版、标准版、深度版 |

如果缺少信息，不要轻易卡住。默认使用“标准版”：最近 3–5 年财务趋势 + 最近 4 个季度 + 当前估值和股价位置 + 核心风险。周期股必须覆盖最近两个完整周期或可比上行段，不受 3–5 年限制。

同时必须先完成公司类型路由，再判断基本面交易模式：

| 字段 | 示例 |
|---|---|
| 主类型 | 高质量成长/复利、成熟现金流/红利防御、周期/商品/产能、资产重估/深度价值、金融资产负债型、困境反转/重组、前盈利高不确定性、事件驱动/特殊情形 |
| 次类型 | 平台、重资产、政策敏感、双重上市等；最多两个 |
| 当前状态 | 高速扩张、成熟、周期底部/上行/顶部、经营恶化、反转、事件等待 |
| 主导价值来源 | 增长持续期、FCF/股息、周期价差、NAV、ROE/资产质量、生存修复、里程碑、事件概率 |
| 分类置信度 | 高/中/低，并说明最强替代分类 |

| 字段 | 示例 |
|---|---|
| 基本面模式 | 模式一：买预期、卖现实；模式二：买现实、买预期；模式三：买现实、卖现实 |
| 当前阶段 | 现实恶化、预期启动、预期验证、现实兑现、预期落空、现实高估 |
| 价格反映 | 尚未反映、部分反映、充分反映、过度反映、无法判断 |
| 主要交易矛盾 | 例如“现货弱但远月期货强”“现实强但估值过度透支”“现金流稳定但故事化高估” |

### 2. 证据收集

公司分析默认把 Wind MCP 作为第一取数入口。凡用户问题涉及 A 股、港股、美股、基金、指数、债券、上市公司公告、财经新闻、宏观经济或行业指标，且内置 Wind MCP 支持该范围时，必须先使用 Wind 获取行情、估值、K 线、财务、股东、事件、技术、风险、公告、新闻、宏观或行业数据；不得先用 Web Search、通用网页、非 Wind 插件或记忆替代。

在 Wind 结构化取数的同时，先调 `knowledge_search` 检索本地知识库中与标的、行业和主题相关的知识卡片（需要全文用 `detail: "full"`）：命中卡片是「别人观点的结构化转述」，按信源分级表归入 C/D 级——只能作为线索与假设来源，不得单独定论，引用时标注卡片 id 并列入「来源与口径」；未命中也如实说明「知识库无相关沉淀」。主题宽泛或不确定时走两级检索：先 `knowledge_graph` 看主体（聚类）分布，再 `knowledge_search` 按 `cluster` 钻取。

调用 Wind 时，优先使用本 skill 内置资源，不依赖外部单独安装的 `wind-mcp-skill`：

| 资源 | 用途 |
|---|---|
| `references/wind-mcp-skill/SKILL.md` | Wind MCP 路由、参数、失败处理和回答规则 |
| `references/wind-mcp-skill/references/tool-contracts.md` | 工具字段、参数、场景和示例 |
| `references/wind-mcp-skill/references/indicators.md` | `indexes` 等指标字段名词典 |
| `references/wind-mcp-skill/scripts/cli.mjs` | Wind MCP 实际调用入口 |

#### Wind MCP 内置安装与配置

分发时直接复制完整 `company-analysis-skill/`；不得包含 `config.json`、`update-state.json`、Key、Token 或其他凭据。接收方只需把目录放入 skills 根目录、确保 Node.js 可用，并从 skill 根目录配置 Key：

```bash
node scripts/wind-mcp-cli.mjs setup-key <WIND_API_KEY> --scope global
```

随后执行最小真实验证：

```bash
node scripts/wind-mcp-cli.mjs call stock_data get_stock_price_indicators '{"windcode":"600519.SH","indexes":"最新成交价,涨跌幅"}'
```

每次调用前读取并遵守 `references/wind-mcp-skill/SKILL.md`；安装、配置优先级、工具路由、参数、错误码和更新方式均以该内置 reference 为准。调用格式：

```bash
node scripts/wind-mcp-cli.mjs call <server_type> <tool_name> '<params_json>'
```

若返回 `AUTH_ERROR`，只按 stdout 的 `error.agent_action` 修复 Key；不得用 Web Search、其它插件或通用工具绕过认证。股票行情、估值、K 线和价格指标能映射到 Wind 专项工具时，不得为了省调用次数改用通用兜底。

Wind 是公司分析的第一取数源，不是原始披露的替代品。财报、公告、监管事件、重大诉讼、管理层表述、回购和分红等核心事实，如果会直接支撑投资结论，仍必须回到公司披露、监管/交易所文件或公司 IR 做核验；Wind 返回值可用于定位、提取、比对和补齐结构化字段。

只有在以下情况才跳过或延后 Wind：Wind MCP 明确超范围；认证、额度、网络或后端故障阻塞且用户允许继续；Wind 无结果或字段不可用；原始公告/监管文件是唯一可信来源；用户明确要求不用 Wind。跳过时必须在报告“来源与口径”中说明原因。

根据市场选择优先信源：

在八大模块分析前，先给出“预期-现实框架”章节。该章节不是替代证据审计，而是把证据转化为交易阶段。

| 项目 | 判断 |
|---|---|
| 基本面模式 | 模式一/模式二/模式三 |

| 失效条件 | 哪些数据出现后，原假设失败 |

不同模式的动作纪律：

| 模式 | 买入或加仓条件 | 减仓或卖出条件 | 必须避免 |
|---|---|---|---|
| 买预期、卖现实 | 现实仍弱但边际预期改善，价格未充分反映；回调不破关键假设可试错或加仓 | 利润兑现、报表好看、市场一致乐观、估值进入强周期乐观区间，或预期落空 | 等现实完全确认后追高；没有失效点地抄底 |
| 买现实、买预期 | 现实经营强，未来增速/空间继续打开，估值仍可解释 | 现实强度下滑、预期被证伪、估值明显透支 | 把短期高景气误判成长期高增长 |
| 买现实、卖现实 | 现金流和分红稳定，估值低，分红覆盖健康 | 估值高、分红覆盖恶化、稳定资产被故事化重估 | 被“新叙事”诱导在高位接盘 |

对周期股，不能把“等待报表完全确认”作为唯一动作。先用历史领先关系判断是否存在研究层面的预期试错窗口，再把右侧确认条件单独列出；两者都不得跳过交易计划所需的价格与风控条件。

关键公式：

```text
自由现金流 FCF = 经营现金流 CFO - 资本开支 Capex
盈利质量 = 经营现金流 CFO / 净利润
毛利率 = 毛利润 / 营业收入
净利率 = 净利润 / 营业收入
资产负债率 = 总负债 / 总资产
存货周转天数 = 365 / 存货周转率
现金分红占 FCF = 分红金额 / 自由现金流
FCF 分红覆盖倍数 = 自由现金流 / 分红金额
周期机械利润敏感性 = 有效销量或产量 × 单位换算 × Δ(实现价格 - 完全成本)
```

## 评分框架

只有在证据足够时才打分。证据不足时写“无法评分”，不要假装精确。

评分权重必须使用 `references/company-type-analysis.md` 的主类型预设。次类型只补充问题和风险，不机械平均多套权重；确需调整时，最多移动两个模块各 5 个百分点，并解释原因。分类置信度低或关键模块无法评分时，不计算总分。

不同主类型的总分不可直接横向比较。跨类型比较必须回到风险调整后的预期收益、证据强度、估值隐含假设和个人适配性。

评分区间：

| 分数 | 含义 |
|---:|---|
| 0–1 | 明显负面 |
| 2 | 偏弱 |
| 3 | 中性 |
| 4 | 偏强 |
| 5 | 明显优秀 |

最终分数不是买卖指令，只是辅助判断。必须同时给出置信度和最强反方证据。

## 估值方法

主估值方法和情景轴必须由 `references/company-type-analysis.md` 的主类型路由决定，不要机械套 PE，也不要因为估值低就反向把公司归类为“价值股”。金融公司不用工业企业 FCF 机械评价；前盈利公司不用 PE；困境公司先算生存与稀释；事件驱动先算概率树；混合型公司先做分部估值和 SOTP。

估值必须和基本面模式联动：

| 模式 | 估值重点 |
|---|---|
| 买预期、卖现实 | 用周期底部/中枢/顶部利润或价格假设做情景；不能用低谷 PE 判断便宜，也不能用顶部 PE 判断便宜 |
| 买现实、买预期 | 同时拆当前经营质量和未来增速空间；重点检查估值是否已过度透支“未来更强” |
| 买现实、卖现实 | 以 FCF yield、股息率、分红覆盖、资产负债表稳健性为核心；警惕高估区讲成长故事 |

估值输出必须使用场景表。非周期公司可使用下行/基准/上行三档；非线性周期公司使用 4–5 档，并在表前写明机构一致预期对应哪一档及数据日期：

| 场景 | 核心经营/价值驱动假设 | 关键财务/事件结果 | 与一致预期关系 | 估值交叉 | 合理价值 | 置信度 |
|---|---|---|---|---|---|---|
| 失效/下行 |  |  |  |  |  |  |
| 基准/当前预期 |  |  |  |  |  |  |
| 上行/超预期 |  |  |  |  |  |  |
| 类型特有场景 4（可选） |  |  |  |  |  |  |
| 类型特有尾部（可选） |  |  |  |  |  | 低 |

周期估值必须同时满足：

- 用全年可持续价格与完全成本测算，不把月度或现货峰值直接年化。
- 用历史市值、PB、当前/未来 BVPS 和阶段匹配的低 PE 交叉验证；不得把峰值利润再乘高景气高倍数。
- 明确哪些数字是机械敏感性、周期利润能力、机构一致预期和单一年度预测，不能混写。
- 从当前市值反推市场隐含的可持续单位价差、利润与持续期，并说明反推对估值方法的依赖。
- A/H 或双重上市先形成统一权益价值，再单列各市场结构性折溢价和每股价值。

## 常见红旗

看到以下情况必须突出提示：

- 利润增长但经营现金流持续恶化。
- 自由现金流长期为负，却持续高分红或回购。
- 商誉/无形资产占净资产比例过高。
- 应收账款、存货增速显著高于收入增速。
- 毛利率持续下滑，管理层却只强调收入增长。
- 单一客户依赖高，客户自身需求不稳定。
- 大股东高比例质押或频繁减持。
- 关联交易复杂且披露不足。
- 管理层多次承诺不兑现。
- 行业由增量市场转向存量博弈，但估值仍按成长股定价。
- 重大监管/诉讼风险未充分反映在估值中。
- 回购发生在高估区间，且主要用于对冲股权激励稀释。
- 周期股现实已经兑现、市场一致乐观，却继续用“买预期”逻辑追高。
- 周期股现实仍弱但预期改善刚启动，却用“现实未确认”完全否定左侧试错价值。
- 所谓“牛市”利润已经落在机构一致预期内，却没有重命名场景或补充真正的强周期条件。
- 把短期价格峰值当全年均价，或把峰值利润与高景气高估值倍数同时使用。
- 用不可复制的供给冲击超级周期直接抬高基准估值。
- 现金流型公司被包装成高成长故事，估值脱离股息率和 FCF 覆盖。
- 成长股现实强但未来增速边际变弱，仍按“现实强”继续提高估值。
- 把“低估”“高增长”或“高股息”本身当成公司商业类型，没有证明主导价值来源。
- 用统一固定权重比较成长、周期、金融、困境和事件驱动公司。
- 金融公司套工业企业 FCF，前盈利公司套 PE，困境公司忽略债务优先级，事件驱动只计算成功收益。
- 公司已从成长转成熟、从成长转周期或从周期转困境，分析路由却没有同步迁移。

## 最终 HTML 报告结构

2. `结论先行`：用摘要卡片列出投资逻辑状态、估值判断、质量判断、最大风险和置信度。

4. `公司类型与分析路由`：主类型、次类型、当前状态、主导价值来源、分类置信度、替代分类和类型迁移。
5. `预期-现实框架`：说明基本面模式、当前现实、市场预期、价格反映程度、当前动作倾向、验证条件和失效条件。
6. `证据审计`：HTML 证据矩阵，覆盖类型命题、支持证据、反方证据、信源等级、证据强度和结论。
7. `跨周期校准与重新定价`：周期股强制加入周期边界、至少两个历史周期/可比上行段、单位经济敏感性、一致预期与场景命名审计、股价领先关系；非周期股删除本节。
8. `核心投资逻辑与最强反方逻辑`。
9. `八大模块分析`：按主类型调整问题深度。
10. `估值与情景测算`：按主类型选择情景轴；周期股使用 4–5 档非线性场景并单列冲击尾部。
11. `评分卡`：使用主类型权重；证据不足时写“无法评分”，不同主类型总分不直接比较。
12. `风险清单与跟踪指标`：优先列类型特有风险。
13. `操作层面的观察点`：区分研究层面的预期试错、右侧确认和可执行交易计划。
14. `一句话结论`。
15. `来源与口径`：列出主要来源、发布日期、数据日期、类型分类证据、机构一致预期日期、周期边界和关键假设。

如果用户只问一个局部问题，例如“为什么下跌”或“估值怎么算”，可以输出压缩版 HTML，但仍必须包含：`<header>`、结论先行、相关图表或数据表、预期-现实判断、证据审计、反方验证、来源与口径。不要退回 Markdown。
