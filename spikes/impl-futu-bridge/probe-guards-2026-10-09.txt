# PR #103 三条非阻断发现的现场复验（2026-10-09）

PR #103（已合并 `ea4986ac`）的独立审查给了四条非阻断发现，其中三条在本次逐条修掉并复验：

| # | 发现 | 修在哪 |
|---|---|---|
| ① | 默认 `accId=0` 时客户端"能下单、不能撤单"：缺 accId 时只能等 OpenD/桥回一句上游错误串，不是结构化拒绝，也无 `accId=0` 撤单的用例 | `packages/connector-futu/src/rest.ts`（`requireAccId`） |
| ② | 桥对 `trdSide`/`orderType` 接受 JSON 布尔（Python 的 `True in (1, 2)` 为真 ⇒ `true` 被当"买入/限价"放行） | `scripts/futu-openapi-bridge.py`（`handle_place_order` 加布尔闸） |
| ③ | `toOrder` 对缺失 `qty` 静默落 0（`row.qty ?? 0`） | `packages/connector-futu/src/index.ts` |

（审查的第 4 条发现——"账户 id 已脱敏"与事实不符——不在本次范围；本文件按既有纪律
**不把账户号写进仓库**，一律用 `<redacted-accId>`。）

- OpenD：`Futu_OpenD` 本机 127.0.0.1:11111（人本已登录，2026-10-09 复验时在线）。
- 桥：本仓 `scripts/futu-openapi-bridge.py`，**旁路端口 11113**（`FUTU_BRIDGE_PORT=11113`）。
  **常驻桥 11112 与它的 LaunchAgent（`com.dshtrading.futu-openapi-bridge`）全程未动**：
  11112 当时本来就无监听，LaunchAgent 服务未加载，plist 未改。
- 账户：OpenD `get_acc_list` 列出 HK SIMULATE 两个（CASH / MARGIN）+ US SIMULATE 一个，
  与 PR #103 现场同一台 OpenD。本次用 HK CASH 与 US 那个，**账户号已替换为
  `<redacted-accId>`**。**一律 SIMULATE**，没有 REAL 账户，也没有做 `unlock_trade`
  （SIMULATE 下单不需要）。
- 复验探针产生的挂单**全部撤掉**，复验结束时 HK / US 现场挂单均为 0 单。

## ① 撤单缺 accId（桥侧 + 客户端侧）

桥侧（原始响应）：

    $ curl -s ... -d '{"orderId":"1","trdEnv":"SIMULATE"}' $B/api/trd/cancel-order
    {"retType": -1, "retMsg": "cancel-order: \u5fc5\u987b\u7ed9 accId \u2014\u2014 \u8fd9\u6761\u8bf7\u6c42\u91cc\u6ca1\u6709 market ...", "data": null}
    $ curl -s ... -d '{"orderId":"1","trdEnv":"SIMULATE","accId":0}' $B/api/trd/cancel-order
    {"retType": -1, "retMsg": "cancel-order: 必须给 accId ...", "data": null}

客户端侧（`npx tsx` 真跑 `FutuRestClient` → 桥 11113 → 真 OpenD；输出原样，账户号已脱敏）：

    [①a] code=TRADING_ACCOUNT_REQUIRED name=TradingServiceError
    [①a] message=Futu: cancel-order 必须显式给 accId（config.accId 或 credentials.accId）——这条请求里没有
          market，HK / US 是两套 trd 上下文，桥不替你猜账户；0 / 缺省在其它调用里意为"用 OpenD 的默认账户"，
          但撤单不接受它
    [①b] code=TRADING_ACCOUNT_REQUIRED          # accId 显式配 0
    [①c] 撤单前挂单 1 单；首行 orderId=9771470 qty=100 trdSide=BUY orderType=ABSOLUTE_LIMIT
    [①c] cancelOrder -> {"orderId":"9771470","status":"canceled"}
    [①c] 撤单后挂单 0 单

**桥日志证明"结构化拒绝"是出站前发生的**（①② 三次布尔拒绝与 ①a/①b 两次缺账户拒绝
都**没有**在桥日志里留下请求——桥根本没被敲到）：

    POST /api/trd/place-order -> retType=-1      # trdSide=true
    POST /api/trd/place-order -> retType=-1      # trdSide=false
    POST /api/trd/place-order -> retType=-1      # orderType=true
    POST /api/trd/place-order -> retType=0       # 对照：整数形态
    POST /api/trd/get-orders -> retType=0        # 对照：挂单快照
    POST /api/trd/cancel-order -> retType=-1     # curl 直打：缺 accId
    POST /api/trd/cancel-order -> retType=-1     # curl 直打：accId=0
    POST /api/trd/get-orders -> retType=0        # ①c 真客户端读挂单
    POST /api/trd/cancel-order -> retType=0      # ①c 真客户端撤单（唯一一条 cancel 出站）
